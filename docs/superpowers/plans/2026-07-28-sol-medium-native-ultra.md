# План выбора координатора Sol medium и нативного режима Ultra

> Для исполнения обязателен последовательный процесс:
> падающий тест, минимальная реализация, целевая проверка, независимая
> рецензия и только затем следующий этап.

**Цель:** сделать `gpt-5.6-sol + medium` предпочтительной парой нового
управляемого корневого диалога, сохранить `gpt-5.6-terra + medium` как
проверенный запасной выбор и автоматически передавать эффективный корневой
уровень `ultra` в нативный Codex до подготовки контроллера.

**Исходная точка:** ветка `codex/implement-adaptive-subagents-v2`, коммит
`ce7c95487d42dd39745c59c1b0aafbace87d979a`. До изменений `make quality`
завершился успешно: 1817 тестов, один штатный пропуск.

## Общие ограничения

- Не менять дочерние `allowedPairs`, оценочную шкалу, профили прав, число
  процессов и четыре инструмента умного хода.
- `gpt-5.6-sol + medium` разрешить только координатору; дочерняя пара
  по-прежнему начинается с `gpt-5.6-sol + high`.
- Явные корневые параметры модели или уровня рассуждений сохранять без
  переписывания.
- Не добавлять команду `codex-ultra`, не менять псевдонимы, квитанцию точки
  входа и её согласователь.
- `codex-native` остаётся явным нативным входом.
- Не менять SQLite-схему и исторический план адаптивных субагентов версии 2.
- Свежий учётный каталог читается контроллером один раз; шлюз не выполняет
  отдельный `model/list`.
- Любое новое поведение сначала закрепляется тестом, который падает по
  ожидаемой причине.
- Канонические данные и отпечатки обновляются существующими генераторами.
