# codex-settings

Центральный каталог настроек, эксплуатационных инструкций и архитектурных
решений Codex. В этой ветке собран путь адаптивных субагентов
версии `0.2.0`. Предыдущая живая проверка опубликована в
[историческом отчёте](docs/analysis/2026-07-20-adaptive-subagents-v2-validation.md).
Живое доказательство самовосстановления после обновления Codex опубликовано в
[отчёте от 4 августа 2026 года](docs/analysis/2026-08-04-codex-update-self-healing-validation.md).

## Совместимость

Установщик каждый раз проверяет стабильную версию Codex. Канонический
стабильный номер не ниже `0.144.4` только допускает выпуск к проверке
возможностей и не является безусловной гарантией совместимости. Затем
сверяются фактические возможности исполняемого файла и доступные учётной
записи пары «модель — уровень рассуждения». Неканонический, предварительный
либо слишком старый выпуск, как и недостаточная возможность, закрывает
адаптивный путь без скрытой замены модели. После отдельного согласования точки
входа обычная новая команда
`codex` включает управляемый интерактивный путь через `codex-highfd` и
`codex-smart`. Для корня без явных параметров свежие сведения учётной записи
сначала выбирают `gpt-5.6-sol` с `medium`; если эта пара недоступна,
показывается ровно одно предупреждение:
`codex-smart: COORDINATOR_PAIR_FALLBACK; gpt-5.6-sol+medium недоступен, используется gpt-5.6-terra+medium`.
После него используется `gpt-5.6-terra` с `medium`. Если свежих сведений нет
либо недоступны обе пары, обычный `codex` всё равно запускает основной Codex,
не навязывая модель и уровень рассуждений; умная часть временно получает
состояние `DEGRADED`. Явно заданные корневые модель и уровень рассуждений
сохраняются. `ultra` запускается нативно: либо сразу
`codex -c 'model_reasoning_effort="ultra"'`, передавая исходные аргументы
настоящему Codex до разрешателя и контроллера, либо через `codex-native`, а
затем `/model`. Уже работающую управляемую сессию нельзя превратить в нативную
через `/model`: нужно выйти и запустить её заново. `pro` — план подписки, а не
уровень рассуждений. Ultra не участвует в дочерней маршрутизации: в дочерних
`allowedPairs` нет `gpt-5.6-sol + medium` и `ultra`.
Команда `codex-native`, профильные псевдонимы и служебные вызовы `help`/`update`
идут в нативный Codex без контроллера; текст после `--` остаётся
пользовательским запросом. Установленная команда `codex-smart` остаётся
диагностической оболочкой. Повторный запуск установщика с тем же отпечатком входов
возвращает `unchanged`; изменение исходников, лексического пути или содержимого
выбранного Codex, а также канонического пути или содержимого выбранного
Python проходит журналируемое обновление. Для рабочего контура требуется
Python не ниже `3.11`; внешние Python-пакеты ему не требуются. `jsonschema` и
`referencing` остаются средствами проверки для разработки и не копируются в
активацию.
Диагностика считает состояние `READY` доказанным только при выбранной паре,
успешной последней проверке каталога и живом командном сокете. В `DEGRADED`
основной Codex и `codex resume --last` доступны, но полная умная готовность не
доказана. При начальном `UNAVAILABLE` умной пары нет; после прежнего
`SELECTED` доказанная пара сохраняется, хотя свежесть каталога временно не
подтверждена. Публичный результат показывает только безопасные поля
`coordinatorReasonCode`, `lastSuccessfulCheckAt` и `nextAttemptAt`. После
неудач проверка повторяется через 5, 30, 120 и 300 секунд; после успеха — раз
в 300 секунд.
Откат возвращает только целую предыдущую активацию. Удаление поддерживается
только с `--retain-data`: база, резервные копии, карантин и отдельная точка
восстановления сохраняются.
