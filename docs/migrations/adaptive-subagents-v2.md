# Переход на adaptive subagents v2

## Исходное состояние

Старый процесс использует профили, пользовательские агенты, навыки и
`codex-highfd` для повышения предела открытых файлов. Он остаётся рабочим до
явного включения новой маршрутизации.

Новая версия добавляет внешний контроллер, отдельные `codex exec`, выбор
модели и уровня рассуждения для каждой подзадачи, восстанавливаемое состояние и
карантин Git. Она не заменяет корневую модель внутри уже начатого диалога.

## Совместимость

Установщик распознаёт:

- отсутствие `codex-highfd`;
- текущий защищённый шаблон;
- точный прежний шаблон старого автономного процесса;
- точный промежуточный шаблон предварительной версии.

Любой иной отпечаток считается чужим и блокирует установку. Прежний файл
сохраняется в резервной копии.

Новый `codex-highfd` по умолчанию запускает настоящий Codex напрямую. Поэтому
существующие aliases продолжают работать без адаптивной маршрутизации.
Умный путь активируется только явно:

```bash
CODEX_SMART_ENABLED=1 ~/.local/bin/codex-highfd
```

## Порядок перехода

1. Завершить активные волны старых субагентов.
2. Зафиксировать `codex --version`, `codex plugin list --json` и
   `codex plugin marketplace list --json`.
3. Просмотреть установку:

   ```bash
   python3 scripts/install_adaptive_subagents.py
   ```

4. Установить без включения:

   ```bash
   python3 scripts/install_adaptive_subagents.py --apply --json
   ```

5. Выполнить:

   ```bash
   python3 scripts/install_adaptive_subagents.py --doctor --json
   ```

   Если получено `AWAITING_HOOK_TRUST`, открыть `/hooks` в обычной
   интерактивной сессии Codex, проверить ровно `userPromptSubmit` и `stop` от
   `codex-smart-subagents@codex-settings-adaptive` и вручную решить вопрос
   доверия. Установщик не меняет доверие и не обходит его проверку.

6. После `status=READY` выполнить:

   ```bash
   python3 scripts/install_adaptive_subagents.py --smoke --json
   ```

7. Провести один явный читающий пробный запуск с
   `CODEX_SMART_ENABLED=1`.
8. Сверить административные `doctor`, `explain`, `report`, `metrics`,
   аттестацию модели, отрицательные пробы прав и неизменность исходного Git.
   При обнаружении незавершённых публикаций сначала выполнить
   `recover --dry-run`; `recover --apply` разрешён только при остановленном
   контроллере, создаёт резервную копию базы и не удаляет ссылки Git либо
   карантинные кандидаты.
9. Решение о постоянном включении принять отдельно после пробного периода.

Корневые `model`, `model_reasoning_effort`, `sandbox_mode` и
`approval_policy` в ходе перехода не меняются. Дочерние процессы изолированы
своими управляемыми профилями и запускаются с `--ignore-user-config`.

## Возврат

Установить `CODEX_SMART_ENABLED=0`, завершить активные маршруты и попытки,
остановить контроллер, затем выполнить просмотр:

```bash
codex-smart-subagents-admin rollback --dry-run
```

После подтверждения:

```bash
codex-smart-subagents-admin rollback --apply
```

Откат восстанавливает прежний `codex-highfd`, адресно удаляет расширение и
локальный рынок, но не заменяет весь актуальный `config.toml`. Это сохраняет
добавленные после установки пользовательские настройки. Резервная копия
остаётся для ручного аварийного восстановления, а карантинные кандидаты не
удаляются автоматически. База состояния также сохраняется.

Если установленная административная ссылка недоступна или повреждена,
использовать аварийный вход из проверенной рабочей копии репозитория:

```bash
python3 scripts/rollback_adaptive_subagents.py
python3 scripts/rollback_adaptive_subagents.py --apply --json
```
