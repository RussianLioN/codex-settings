# Консилиум по восстановлению Codex после обновления Homebrew

Дата: 2026-08-04.

## Решение

Консилиум поддержал узкое исправление существующего контура
самовосстановления без новой службы, команды, схемы или специальной ветви для
Homebrew.

`resolvedPathAtCapture` остаётся обязательным абсолютным и связанным с
квитанциями значением, но после принятия активации считается историческим
фактом. Его прежняя физическая цель не обязана продолжать существовать.
Текущий `lexicalPath` и старый неизменяемый снимок проверяются независимо:

1. текущий лексический путь строго разрешается, проверяется на исполнимость и
   устойчиво хешируется;
2. прежний снимок проверяется как частный файл режима `0500` с сохранённым
   SHA-256;
3. при различии пути или отпечатка шлюз остаётся `READY` на прежнем снимке и
   возвращает доказанный `source_drift`;
4. запрос согласования повторно доказывает текущую цель, не раскрывая
   исторический путь;
5. квитанция владения установщика связывается с лексическим путём из
   манифеста, а не с выбранным для запуска прежним снимком;
6. административное чтение использует ту же лексическую привязку и поэтому
   остаётся доступным во время доказанного дрейфа.

Отдельная загрузочная ветвь установщика отклонена: она дублировала бы уже
существующие снимок, капсулу, согласователь, подготовку, журнал и квитанции.
Ручное восстановление Codex 0.145.0 также отклонено как временный обход,
зависящий от Homebrew.

Уровень согласия: **большинство**. Восемь ролей поддержали выбранную границу
непосредственно либо с дополнительными предостережениями. Четыре роли
предпочли отдельную загрузочную ветвь установщика. Одна роль предпочла ручной
или операторски подтверждённый переход. Финальная приёмочная роль не нашла
иного архитектурного блокера.

Проведены три последовательные волны: шесть, шесть и одна роль. Перед каждой
волной проверялись файловые дескрипторы. Проверки вернули `OK`; запас составил
3986, 3236 и 3160 дескрипторов соответственно. Все роли работали только на
чтение и не меняли файлы.

## Подтверждённая причина

Живой `/opt/homebrew/bin/codex` разрешается в выпуск 0.146.0. Манифест
принятой активации хранит физический путь выпуска 0.145.0, удалённый Homebrew.
Старый снимок существует, имеет режим `0500` и правильный SHA-256.

Цепочка блокировки состоит из четырёх ошибок:

1. `ActivationResolver._verify_ready_source()` вызывает
   `captured.resolve(strict=True)` до проверки снимка и возвращает
   `SOURCE_CHANGED`;
2. построитель запроса согласования повторно раскрывает тот же исторический
   путь и сравнивает его с новой текущей целью;
3. доказательство перехода сравнивает `installerReceipt.codexBinary` с
   `decision.executable`, хотя при дрейфе последний является старым снимком,
   а квитанция хранит устойчивый лексический путь;
4. административное состояние повторяет то же неверное сравнение и поэтому
   сообщает `INSTALLER_RECEIPT_MISMATCH` для доказанной активации на снимке.

Изменение списка поддерживаемых версий не требуется. Текущий установщик уже
включает путь и SHA-256 выбранного Codex в `sourceDigest`, поэтому смена
двоичного файла входит в штатную ветвь обновления.

## Граница реализации

Изменить только:

- `activation_gateway_v2.py` — проверку источника и построение запроса
  согласования;
- `activation_transition_v2.py` — привязку квитанции владения к лексическому
  пути манифеста;
- `admin_state_v2.py` — ту же привязку для административного состояния;
- соответствующие модульные и сквозные проверки.

Не изменять установщик, форматы манифеста и квитанций, материализатор,
Homebrew или пользовательские данные.

## Обязательная приёмка

| Случай | Ожидаемый результат |
|---|---|
| Старая цель существует и совпадает | `READY`, без дрейфа |
| Старая цель удалена, текущий Codex совместим | `READY` на снимке, одна новая активация |
| Повтор после принятия | без дрейфа; `--apply` возвращает `unchanged` |
| Текущий файл меняется между решением и запросом | отказ до запуска установщика |
| Старый снимок или его доказательство повреждены | закрытый отказ |
| Квитанция содержит чужой лексический путь | закрытый отказ |
| Будущий совместимый стабильный выпуск | одна штатная новая активация |
| Будущий несовместимый выпуск | прежний проверенный снимок остаётся активным |

Финальное доказательство выполняется на живой установке: два последовательных
`--apply`, проверка состояния и интерактивный запуск обычного `codex` из
проекта `datacanvas`. До этого сообщение `SOURCE_CHANGED` не считается
исправленным.
