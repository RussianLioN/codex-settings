# Решение 001: внешний контроллер адаптивных субагентов

## Статус

Принято.

## Дата

2026-07-16.

## Контекст

Codex CLI 0.144.4 позволяет выбрать модель и уровень рассуждения при запуске
сессии или дочернего `codex exec`, но не предоставляет надёжного программного
переключения модели уже работающей корневой сессии. Встроенные субагенты
наследуют часть настроек родителя, а их жизненный цикл не образует отдельную
границу безопасности.

Нужен режим, в котором обычная корневая сессия остаётся координатором, а
независимые задачи передаются внешнему контроллеру. Контроллер должен:

- детерминированно решать, нужна ли передача;
- выбирать модель и уровень рассуждения для каждой задачи;
- запускать дочерний `codex exec` с явной конфигурацией;
- ограничивать параллелизм и вложенность;
- хранить восстанавливаемое состояние;
- не применять изменения дочернего автора к исходному репозиторию;
- выдавать только проверенный карантинный кандидат.

## Решение

Реализовать самодостаточное расширение `codex-smart-subagents` со следующими
границами:

1. Корневая интерактивная сессия не меняет модель автоматически. Она получает
   четыре узких служебных вызова:
   `smart_plan`, `smart_start`, `smart_wait`, `smart_cancel`.
2. Внешний контроллер запускает отдельные `codex exec` с выбранными моделью,
   уровнем рассуждения и профилем прав.
3. Все входы от модели проверяются строгими схемами. Модель не передаёт пути,
   команды, переменные окружения, модель, уровень рассуждения или права.
4. Читающие задачи работают со снимком. Пишущая задача допускается только при
   чистом исходном репозитории и всегда создаёт кандидат в отдельном
   карантинном хранилище Git.
5. В первой версии отсутствует применение, слияние, публикация и изменение
   исходных ссылок Git. Проверенный кандидат остаётся карантинным артефактом.
6. Корневая сессия с полным доступом остаётся доверенным координатором, а не
   границей безопасности. Граница безопасности находится в контроллере,
   разрешённых профилях, снимках и карантине.
7. Пограничное решение допускает ровно одну независимую переклассификацию
   Terra/high. Одноразовая привязка хода и однополётный расчёт не позволяют
   повторам породить дополнительные модельные вызовы.
8. Все подсистемы внешнего запуска используют общий счётчик процессов.
   Пограничная оценка дополнительно ограничена шестью местами, а Sol — двумя.
9. Непрозрачные область, профиль артефакта и профиль проверки являются
   ссылками на активный каталог, а не произвольными строками.
10. Фактические модель и уровень рассуждения подтверждаются по официальным
    полям локальной телеметрии; состояние SQLite каждого дочернего процесса
    направляется в отдельный временный `CODEX_SQLITE_HOME`.
11. Одноразовый токен телеметрии передаётся только через
    `OTEL_EXPORTER_OTLP_LOGS_HEADERS`, отсутствует в аргументах и не наследуется
    командами модели. Штатные ссылки `arg0` Codex разрешаются только по точному
    контракту версии 0.144.4 и только на запущенный исполняемый файл.

## Рассмотренные варианты

### Короткая инструкция в AGENTS.md

Полезна как подсказка, но не обеспечивает детерминированный выбор модели,
ограничение прав, восстановление состояния, идемпотентность и карантин Git.

### Только пользовательские агенты Codex

Позволяют закрепить модель за ролью, но не дают требуемого динамического выбора
для каждой задачи и наследуют ограничения родительской сессии.

### Замена модели корневой сессии

Не имеет подтверждённого программного интерфейса в целевой версии CLI и
разрушает воспроизводимость одного диалога.

### Непосредственное применение правок дочернего автора

Упрощает путь результата, но создаёт неприемлемый риск изменения исходного
рабочего дерева, индекса и ссылок Git непроверенным выводом модели.

## Последствия

- Появляется отдельный локальный процесс и база SQLite.
- Задержка возрастает из-за классификации, снимка, проверок и аттестации.
- Результаты первой версии требуют явного последующего решения человека или
  отдельного доверенного процесса интеграции.
- Контракт можно расширить новой версией схемы, не меняя четыре исходных
  служебных вызова несовместимым образом.
