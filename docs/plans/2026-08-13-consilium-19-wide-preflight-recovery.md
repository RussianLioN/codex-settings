# Consilium 19 — план реализации

> **Для агентных исполнителей:** обязательно применять `superpowers:subagent-driven-development` (предпочтительно) или `superpowers:executing-plans`. Ход выполнения отмечается флажками.

**Цель:** восстановить безопасный и воспроизводимый допуск широкой волны `consilium`, чтобы решение о 19 ролях одновременно учитывало доверие к навыку и фактически доступную общую ёмкость машины.

**Архитектура:** `validate_wide_wave_manifest.py` остаётся единственным валидатором состава и доверия. `codex_capacity.py prepare-wave` остаётся единственным источником `allowed_wave_size`; врач файловых дескрипторов передаёт ему свой уже проверенный доверенный ввод и выводит его решение в совместимом машинном протоколе. Установщик копирует единый согласованный набор исходников и реестр в изолированный профиль атомарно, с квитанцией и откатом.

**Технологии:** Python 3, zsh, JSON, SQLite-состояние ограничителя ёмкости, `unittest`, SHA-256, Git.

## Глобальные ограничения

- Не включать хуки и смарт-запуск; сохранять `[features] hooks = false`.
- Не изменять основной `CODEX_HOME`, `~/.codex/config.toml` или установленный контур до отдельного одобрения владельца. Все испытания выполнять в новом изолированном `CODEX_HOME`.
- Не считать четыре слота текущего интерфейса доказательством возможности плоского запуска 19 ролей. Успех проверки отличается от запуска 19 ролей.
- Любое несовпадение SHA-256, вида исполнения, запасного порядка, размера волны или состава манифеста завершает предварительную проверку закрывающим отказом.
- Не переносить исправление в `agents-skills` в этом наборе изменений. Изменение контракта его навыка выпускается отдельным согласованным изменением.
- Не удалять журналы, резервные копии, базы или прежние активации.

## Изменяемые файлы

- `config/trusted-wide-wave-skills.json` — нормативные записи доверенных навыков и точные хэши их установленной версии.
- `scripts/validate_wide_wave_manifest.py` — строгая проверка значений `execution_kind` и `fallback`, а не только их непустоты.
- `scripts/codex_fd_doctor.sh` — мост к `prepare-wave` и публикация `allowed_wave_size` с единой семантикой `OK`, `WARN`, `BLOCK`.
- `scripts/apply_runtime_fd_guardrails.py` и `scripts/codex_autonomous_rollback.py` — атомарная установка, квитанция, сверка и откат полного набора, включая ограничитель ёмкости.
- `tests/smart_subagents/test_wide_wave_manifest.py`, `tests/smart_subagents/test_fd_doctor_process_inventory.py`, `tests/smart_subagents/test_codex_capacity.py`, `tests/smart_subagents/test_runtime_fd_guardrail_installer.py` — регрессии доверия, допуска, установки и отката.
- Этот план и документ анализа первопричины (RCA) — маршрутизация и
  эксплуатационная граница.

### Задача 1: зафиксировать доверенный договор и его отрицательные случаи

**Файлы:**

- Изменить: `config/trusted-wide-wave-skills.json`.
- Изменить: `scripts/validate_wide_wave_manifest.py`.
- Испытать: `tests/smart_subagents/test_wide_wave_manifest.py`.

**Вход:** фактические файлы `SKILL.md` установленных версий трёх навыков.

**Результат:** реестр с тремя точно закреплёнными записями и валидатор, который принимает только известные сочетания значений.

- [ ] Сначала добавить красные случаи: пустой реестр даёт `unknown_skill`; подменённый байт `SKILL.md` даёт `skill_hash_mismatch`; `wave_size=20` для `consilium` даёт `wave_size_exceeds_trusted_max`; неизвестные `execution_kind` и `fallback` дают отдельные причины.
- [ ] Сверить SHA-256 фактических установленных `SKILL.md`, затем записать только их в реестр:

  ```json
  {
    "skill_id": "consilium",
    "sha256": "98dc2531865512f8628326d03ed8152bb2d896909eb6353ff200b3a798799264",
    "max_live_wave": 19,
    "execution_kind": "flat-trusted-wide-wave",
    "fallback": "6+6+6+1"
  }
  ```

  Для `expert-consilium` и `consilium-lean` использовать только заново вычисленные хэши и их текущие договорные максимумы, а не догадки или перенос старого хэша.
- [ ] Ввести закрытые множества: `execution_kind` допускает только `flat-trusted-wide-wave`; `fallback` — `6+6+6+1`, `6+6+1` или `chunks<=6` только для соответствующих трёх `skill_id`.
- [ ] Запустить:

  ```bash
  python3 -m unittest tests.smart_subagents.test_wide_wave_manifest -v
  ```

  Ожидаемый результат: все положительные и отрицательные случаи проходят.
- [ ] Создать отдельный коммит `fix: restore trusted wide-wave registry`.

### Задача 2: сделать размер допуска единым результатом предварительной проверки

**Файлы:**

- Изменить: `scripts/codex_fd_doctor.sh`.
- При необходимости изменить: `scripts/codex_capacity.py` только для стабильного беззаписного машинного вызова `prepare-wave`.
- Испытать: `tests/smart_subagents/test_fd_doctor_process_inventory.py` и `tests/smart_subagents/test_codex_capacity.py`.

**Вход:** проверенный манифест, доверенный навык, снимок наблюдателя и состояние общей очереди.

**Результат:** в выводе врача всегда есть целое `allowed_wave_size`; успех широкой волны возможен только если `allowed_wave_size >= wave_size`.

- [ ] Добавить красные случаи: доверенный размер 19 при пропускной способности 6 возвращает `WARN` и `allowed_wave_size=6`; доверенный размер 19 при пропускной способности 19 возвращает `OK` и `allowed_wave_size=19`; любой отказ доверия или наблюдателя возвращает `BLOCK` и `allowed_wave_size=0`.
- [ ] После успешной проверки манифеста вызвать `codex_capacity.py prepare-wave` с теми же `--wave-size`, `--wide-wave-skill-id`, `--wide-wave-skill-file` и `--wide-wave-manifest`. Не дублировать расчёт ёмкости в zsh и не создавать резерв или аренду в этой диагностической операции.
- [ ] Нормализовать результат врача:

  ```text
  status=OK|WARN|BLOCK
  wave_size=<запрошенный размер>
  allowed_wave_size=<0..20>
  capacity_decision=ALLOW|WARN|BLOCK
  reasons=<детерминированный список или none>
  ```

  Для широкой волны `OK` требует одновременно доверенный манифест, отсутствие иных блокировок и `allowed_wave_size >= wave_size`. `WARN` сохраняет фактически допустимый размер для договорного разбиения на волны. `BLOCK` всегда устанавливает ноль.
- [ ] Уточнить подпись `agent_thread_cap`: выводить `agent_thread_cap=not_configured`, если ключ не найден; не менять статус только из-за этого поля. Добавить испытание этого текста.
- [ ] Запустить:

  ```bash
  python3 -m unittest \
    tests.smart_subagents.test_fd_doctor_process_inventory \
    tests.smart_subagents.test_codex_capacity -v
  ```

  Ожидаемый результат: доверие и ёмкость проверяются одной цепочкой, а диагностический ключ не маскирует действительную причину отказа.
- [ ] Создать отдельный коммит `fix: unify wide-wave admission preflight`.
