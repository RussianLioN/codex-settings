# План защиты Codex по запасу процессов

> **Для исполнителя:** выполнять по этапам с падающими тестами до изменения рабочего кода и с независимой проверкой перед завершением.

**Цель:** не допускать запуска новой волны субагентов, если пользовательский лимит процессов почти исчерпан или число процессов `node_repl` уже несовместимо с допустимым числом потоков Codex.

**Архитектура:** расширить существующий `codex_fd_doctor.sh` второй независимой проверкой ресурсов. Проверка вычисляет эффективный предел процессов, текущее число процессов пользователя, динамический резерв для запрошенной волны и верхнюю границу `node_repl`. Она только возвращает `OK`, `WARN` или `BLOCK` и никогда не завершает процессы автоматически.

**Средства:** `zsh`, `ps`, `launchctl`, Python `unittest`, действующий валидатор автономного процесса и установщик локальных ограничителей.

## Инварианты

- Существующая проверка файловых дескрипторов и нативного потолка 20 потоков сохраняется.
- Требуемый запас процессов равен `128 + 20 * wave_size`.
- Эффективный предел выбирается из доступных положительных числовых ограничений `ulimit`, `launchctl` и ядра; значение `unlimited` не считается доказанным пределом.
- Отсутствие доказанного предела, сбой подсчёта процессов или нечисловая инвентаризация Codex/`node_repl` блокирует волну с причиной `process_budget_unavailable`.
- Запас ниже требуемого блокирует волну с причиной `process_headroom_below_<N>`.
- Число `node_repl` выше `20 * max(codex_processes, 1)` блокирует волну с причиной `node_repl_processes_exceed_thread_capacity`.
- Вывод содержит `process_limit`, `user_process_count`, `process_headroom`, `required_process_headroom` и `max_expected_node_repl_processes`.
- Автоматическое завершение процессов запрещено.

## Этап 1. Зафиксировать красные тесты бюджета процессов

**Файлы:**

- изменить `tests/smart_subagents/test_autonomous_workflow.py`;
- изменить `scripts/validate_autonomous_workflow.py`.

1. Добавить управляемые переменные окружения для предела и текущего числа процессов.
2. Добавить случаи: безопасный запас, точная граница, недостаточный запас, широкая волна, недоступный бюджет и превышение числа `node_repl`.
3. Проверить обязательные поля вывода и точные причины блокировки.
4. Запустить только новые тесты и зафиксировать ожидаемое падение до изменения `codex_fd_doctor.sh`.

## Этап 2. Реализовать проверку без побочных действий

**Файл:** `scripts/codex_fd_doctor.sh`.

1. Прочитать пределы процессов из управляемых переменных или локальных источников.
2. Нормализовать положительные числовые пределы и выбрать минимальный доказанный предел.
3. Посчитать процессы пользователя, запас и требуемый резерв.
4. Добавить блокировки бюджета и вместимости `node_repl`.
5. Вывести новые диагностические поля, не меняя договор кодов возврата `0/1/2`.
6. Повторить целевые тесты до зелёного результата.
