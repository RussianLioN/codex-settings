# Переход на адаптивных субагентов версии 2

## Назначение

Версия 2 добавляет отдельную команду `codex-smart`, внешний контроллер,
выбор модели и уровня рассуждения для каждого узла, долговечное состояние и
карантин Git. Обычная команда `codex` не заменяется. Корневая модель уже
начатого диалога не переключается: переход применяется только к новому
диалогу, запущенному через `codex-smart`.

Прежние пользовательские профили, агенты и навыки не удаляются и могут
использоваться отдельно. Версия 2 не меняет пользовательские значения
`model`, `model_reasoning_effort`, `sandbox_mode` и `approval_policy`.

## Перед переходом

1. Завершить активные дочерние процессы прежнего рабочего контура.
2. Зафиксировать текущее состояние:

   ```bash
   codex --version
   codex plugin list --json
   codex plugin marketplace list --json
   ```

3. Убедиться, что используется проверенная стабильная версия Codex:
   `0.144.4`, `0.144.5`, `0.144.6` или `0.145.0`. Неизвестная будущая версия запускается
   как обычный Codex, пока её точки подключения не будут отдельно проверены.
   Для допущенной версии установщик также проверяет фактические возможности
   выбранного исполняемого файла и доступные учётной записи пары
   «модель — уровень рассуждения».

## Просмотр и установка

Из корня этого репозитория сначала выполнить просмотр без изменений:

```bash
python3 scripts/install_adaptive_subagents.py --json
```

Затем применить установку и выполнить две независимые проверки:

```bash
python3 scripts/install_adaptive_subagents.py --apply --json
python3 scripts/install_adaptive_subagents.py --doctor --json
python3 scripts/install_adaptive_subagents.py --smoke --json
```

Нормальная готовность — `readiness=READY`; первая установка возвращает
`status=installed`. Повтор того же `--apply` с тем же отпечатком исходников
должен вернуть `status=unchanged` и не создавать вторую активацию или новые
стабильные ссылки.

Если отпечаток исходников, пути либо содержимого выбранного исполняемого файла
Codex изменился, тот же `--apply` выполняет управляемое обновление: закрывает
новые допуски, осушает контроллер, фиксирует журнал, публикует новую активацию
и открывает шлюз только после принятия нового контроллера и квитанции.
Отдельного флага `--upgrade` нет.

При первом интерактивном запуске Codex может запросить решение о доверии
хукам. В `/hooks` следует проверить источник
`codex-smart-subagents@codex-settings-adaptive` и записи
`UserPromptSubmit` и `Stop`, после чего принять решение вручную. Установщик
не изменяет доверие пользователя.

## Первый адаптивный диалог

Запустить новый диалог:

```bash
~/.local/bin/codex-smart
```

Для первого испытания рекомендуется чистый тестовый репозиторий и только
читающая задача. После завершения проверить состояние:

```bash
~/.local/bin/codex-smart-subagents-admin status
~/.local/bin/codex-smart-subagents-admin doctor
```

Команда `inspect` с полученным `routeId` показывает выбранные для каждого
узла модель и уровень рассуждения, попытки, события и кандидаты:

```bash
~/.local/bin/codex-smart-subagents-admin inspect \
  route2_0123456789abcdef0123456789abcdef
```

`inspect` не возвращает зависимости графа: их следует сохранить из
`smart_plan` и сопоставить с порядком событий.
`terminalResult` возвращает `smart_wait`, а не административная проекция.

После читающего маршрута можно проверить граф «два независимых читателя →
итоговый синтез». Пишущую задачу следует запускать последней: её результат
остаётся отдельным кандидатом и не применяется к исходной рабочей копии
автоматически.

## Что даёт и чего не даёт AGENTS.md

Инструкция в проектном `AGENTS.md` может попросить обычный Codex делегировать
независимые подзадачи. Отдельная пользовательская роль в TOML также может
закрепить одну модель и один уровень рассуждения; незаданные параметры роли
наследуются от родительского сеанса.

Это не включает путь версии 2. Сам по себе `AGENTS.md` не выбирает и не
подтверждает отдельную пару «модель — уровень рассуждения» для каждого узла,
не обеспечивает повторяемый запуск, восстановление и карантин пишущего
результата. Для этих гарантий новый диалог следует запускать через
`~/.local/bin/codex-smart`. Подробное сравнение находится в разделе
[«Корневая модель и роль AGENTS.md»](../../plugins/codex-smart-subagents/README.md#корневая-модель-и-роль-agentsmd).

## Управление установленной версией

Каждая изменяющая команда сначала поддерживает просмотр без изменений, затем
явное применение:

```bash
python3 scripts/install_adaptive_subagents.py --rollback --preview --json
python3 scripts/install_adaptive_subagents.py --rollback --apply --json

python3 scripts/install_adaptive_subagents.py --uninstall --retain-data --preview --json
python3 scripts/install_adaptive_subagents.py --uninstall --retain-data --apply --json

python3 scripts/install_adaptive_subagents.py --recover --preview --json
python3 scripts/install_adaptive_subagents.py --recover --apply --json

python3 scripts/install_adaptive_subagents.py --cleanup --preview --json
python3 scripts/install_adaptive_subagents.py --cleanup --apply --json

python3 scripts/install_adaptive_subagents.py --inspect --json
```

Откат принимает только полностью доказанную предыдущую активацию. Удаление без
`--retain-data` запрещено: база, резервные копии, карантин и независимая точка
восстановления остаются на месте. `recover` продолжает точно найденный журнал
установки, обновления, отката или удаления. При прерванном удалении
`--recover --preview --json` показывает
`extensions.lifecycleAdapter.journalKind=uninstall` и сохранённый
`extensions.lifecycleAdapter.internalOperationId`; верхнее поле `operationId`
при просмотре остаётся пустым. `--recover --apply --json` продолжает тот же
`operationId`. Равнозначно можно повторить
`--uninstall --retain-data --apply --json`: оба пути используют один журнал.
`cleanup` удаляет только уже неиспользуемые поколения, сохраняет старые
commit-квитанции и после прерывания продолжается повтором
`--cleanup --apply --json`. Повтор завершённой команды возвращает `unchanged`,
не создавая второй операции.

Коды завершения едины: `0` — нет блокирующей проблемы; `2` — команда
выполнена, но готовность не `READY`; `64` — неверное сочетание параметров;
`70` — внутренняя либо структурная ошибка; `75` — доказанная временная
занятость. Строгий JSON печатается и для диагностируемых ненулевых исходов.

## Прерывание и восстановление

Если контроллер был прерван, сначала построить план без изменений:

```bash
~/.local/bin/codex-smart-subagents-admin recover --dry-run
```

Если контроллер ещё работает, завершить только принятую личность контроллера,
повторно построить план и затем применить его:

```bash
~/.local/bin/codex-smart-subagents-admin stop
~/.local/bin/codex-smart-subagents-admin recover --dry-run
~/.local/bin/codex-smart-subagents-admin recover --apply
```

`stop` сверяет идентичность процесса до отправки сигнала. `recover --apply`
разрешён только при остановленном контроллере и выполняет лишь доказанные
действия. Повтор после успешного восстановления не должен создавать новые
изменения.

Эти административные команды восстанавливают маршруты, дочерние процессы,
временные области и публикации кандидатов. Если прервалась установка,
обновление, откат или удаление, используется другая пара команд установщика:

```bash
python3 scripts/install_adaptive_subagents.py --recover --preview --json
python3 scripts/install_adaptive_subagents.py --recover --apply --json
```

Для удаления пробный результат показывает
`extensions.lifecycleAdapter.journalKind=uninstall` и сохранённый
`extensions.lifecycleAdapter.internalOperationId`; верхнее поле `operationId`
при просмотре остаётся пустым. Применение продолжает тот же `operationId`.
Тот же журнал можно продолжить точным повтором
`--uninstall --retain-data --apply --json`. Уборка в общий установочный
`--recover` не входит и продолжается повтором `--cleanup --apply --json`.

## Временный возврат к обычному Codex

Завершить активный адаптивный диалог и запускать обычную команду:

```bash
codex
```

Это не удаляет установку и не меняет пользовательскую конфигурацию. Не следует
вручную удалять квитанцию, активацию, стабильные ссылки, базу или карантинные
кандидаты: ручное удаление разрушает доказательство владения, необходимое для
управляемого обновления и удаления.
