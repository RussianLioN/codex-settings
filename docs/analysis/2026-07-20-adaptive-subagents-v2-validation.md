## Что делает решение

`codex-smart` оставляет корневой диалог координатором, а независимые
проверяемые подзадачи передаёт отдельным процессам `codex exec`. Для каждого
узла контроллер отдельно выбирает роль, модель и `reasoningEffort`, запускает
дочерний Codex, проверяет фактическую пару запуска и возвращает корневому
диалогу проверенный результат. Пишущий узел, если он есть, публикует только
изолированного кандидата; исходная рабочая копия не меняется автоматически.

Полная схема запроса, пишущего кандидата, жизненного цикла установки и
восстановления находится в
[диаграммах потока](adaptive-subagents-v2-flow.md#полный-поток-запроса).
Порядок установки, диагностики и восстановления описан в
[операционной инструкции](../runbooks/adaptive-subagents-v2-operations.md).

## Как пользоваться из чистой обычной копии Git

1. Подготовить обычную чистую копию Git с зафиксированным `HEAD`.
2. Убедиться, что установка имеет состояние `READY`:

```bash
python3 scripts/install_adaptive_subagents.py --doctor --json
```

3. Запустить новый корневой диалог:

```bash
~/.local/bin/codex-smart
```

4. Дать независимую проверяемую подзадачу. Для чтения результата взять
`routeId` из ответа умного хода и посмотреть маршрут:

```bash
~/.local/bin/codex-smart-subagents-admin inspect ROUTE_ID --limit 100
```

## Как выбираются модель и reasoningEffort

Маршрутизатор сначала решает, нужен ли субагент: `direct`, `clarify` или
`delegate`. Только для `delegate` он выбирает пару для каждого узла.

Модель и глубина рассуждений выбираются отдельно. Простые задачи направляются
на `gpt-5.6-luna`, средние инженерные задачи - на `gpt-5.6-terra`, сложные
архитектурные, рискованные или требующие высокой доказательности - на
`gpt-5.6-sol`. `reasoningEffort` повышается отдельной шкалой по сложности,
объёму, цене ошибки и неопределённости. Недоступная пара не заменяется
скрытым понижением.

В проверенном маршруте роль `researcher` получила выбранную и фактически
наблюдённую модель `gpt-5.6-luna` и `reasoningEffort` `low`.

## Ограничения

- Проверка подтверждает конкретный читающий маршрут, а не все возможные
  пишущие сценарии.
- Корневая модель уже начатого диалога не переключается посреди хода.
- Для работы нужен поддержанный интерактивный запуск через `codex-smart` и
  чистая обычная копия Git.
- Кандидаты пишущих узлов не применяются, не сливаются и не отправляются
  автоматически.
- Отсутствующая модель или уровень рассуждений завершает адаптивный запуск
  явным отказом, а не скрытым понижением.
- Финальная активация после переустановки и финальный `sourceDigest` в этом
  отчёте не заявлены.
